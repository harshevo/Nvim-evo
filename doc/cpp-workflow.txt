*cpp-workflow.txt*     C/C++ editing, building, documentation and debugging

C/C++ WORKFLOW                                              *cpp-workflow*

Leader is Space. Use :CppHelp to open this guide.

FORMAT
  Saving formats C/C++ using clang-format.yaml in the Neovim configuration.
  Functions, classes, namespaces and control-flow braces use new lines:
>
  int add(int left, int right)
  {
    return left + right;
  }
<
  Empty functions also use separate brace lines. This explicit style takes
  precedence over a project's .clang-format file. Indentation is two spaces.
  Space cf      Format C/C++ asynchronously
  Space mp      Format file (or selected range in visual mode)
  :KickstartFormatToggle  Enable/disable formatting on save

CHECK AND RUN
  Space b       Open/close error split immediately; check in background
  Space B       Save and perform full project build
  Enter / o     Jump to the selected error from the error split
  j / k         Select next/previous error in the split
  q / Esc       Close the error split
  Space cn/cp   Next/previous compiler error
  ]d / [d       Next/previous language-server diagnostic
  Space q       Detailed diagnostic at the cursor
  Space R       Save, compile and run this file
  Space r       Save, rebuild and run the project
  :RunStop      Stop runner build/program and close output

  Checks save edited source buffers, including headers. Standalone checks use
  -fsyntax-only (no link step); CMake/Make projects build incrementally. Results
  stay hidden if you close the error split while a check is running. Reopening
  unchanged results within two seconds does not start another check.

  Standalone compilation uses C17/C++20, -O0 -g, -Wall and -Wextra. Failed saves
  or builds never launch an old executable. Space R runs one translation unit; use
  Space r for a project with multiple source files. Use :RunNow arguments for
  single-file command-line arguments. Terminal input works normally; Esc then
  H closes the runner output. Space R from output saves/rebuilds the source again.

COMPLETION AND NAVIGATION
  K             Signature, types and available documentation; K again focuses
  gK            Signature help at a call
  Ctrl-k        Signature help while typing
  Ctrl-Space    Request completion
  Ctrl-n/p      Select completion
  Enter         Accept completion
  Tab/Shift-Tab Navigate completion/snippet fields
  gd / gD       Definition / declaration
  gr / gi       References / implementation
  gT            Type definition
  Ctrl-o        Return after navigation
  Space cr      Rename symbol across the project
  Space ca      Code action / suggested fix
  Space ch      Switch source and header
  Space cs      Search symbols in this file
  Space ci      Toggle inline parameter/type hints

  clangd uses the project's compilation database, .clangd or compile_flags.txt.
  Databases in build/, out/Debug, out/Release and common CMake directories are
  detected. Run :CppRestart after creating or switching build directories.
  Projects retain their own language standards, definitions and include paths.
  Standalone files receive matching C17/C++20 flags. clangd may take a moment
  to index large projects before all cross-file results become available.

DOCUMENTATION
  Space cm      C/POSIX manual for symbol under cursor (section 3, then 2)
  :CppMan name  Open a named system manual
  Space fm      Search installed manual pages; fetched asynchronously and cached
  :ManSearch!   Refresh the manual index
  Space cR      Search cppreference in the browser (requires internet)
  :CppReference name  Search a named C/C++ API on cppreference

  K reads signatures and comments from your actual headers through clangd.
  System manuals are available offline. Third-party documentation depends on
  installed headers/manuals; cppreference covers the standard C/C++ library.

DEBUG
  Space dc      Save, rebuild and debug; continues an active session
  Space db      Toggle source breakpoint
  Space do      Step over
  Space di      Step into
  Space dO      Step out
  Space ds      Inspect local variables/scopes
  Space df      Inspect stack frames
  Space dB      List breakpoints
  Space dt      Conditional breakpoint
  Space dn      Run to cursor
  Space de      Inspect expression under cursor
  Space dr      Toggle debugger REPL (expressions and debugger commands)
  Space dq      Terminate debug session
  :CppDebug     Save, rebuild and launch LLDB

  nvim-dap and LLDB load only when requested. Standalone builds include debug
  symbols; fresh CMake build directories default to Debug. Existing project
  build types are preserved: choose Debug (Space mt) and regenerate (Space mg)
  if breakpoints are unavailable. CMake targets are selected automatically or
  through a picker. Make projects prompt for the executable after building.

PROJECT COMMANDS AND SHORTCUTS
  Pause after Space to see available shortcuts (WhichKey).
  Space pp      C/C++ command palette
  Space fk      Search all configured shortcuts
  Space ps      Save project session (files, tabs, splits, folds and directory)
  Space pl      Restore project session, including saved build preset

BUILD PRESETS AND CACHE
  Space mP/mt   Choose and configure a CMake preset
  Space mg      Configure the current preset (choose one if none is active)
  Space ml      Build and select the executable target
  Space mI      Add local Debug, Release, ASan and UBSan presets
  Space mC      Show compiler cache statistics
  :CppPreset name  Configure and activate a named preset

  If a CMake project has no presets, choosing one creates CMakeUserPresets.json
  with nvim-debug, nvim-release, nvim-asan and nvim-ubsan. Existing project
  presets are available in the same picker; existing user entries are preserved.
  Keep CMakeUserPresets.json out of version control. Selected presets persist
  per project and drive build/run/test/debug commands and clangd's database.
  Configure first, then Space r builds and runs the chosen executable.

  New builds prefer Ninja. Existing build generators are preserved. CMake
  compiler launchers and standalone compilation use ccache when installed;
  linking is always fresh. Presets control their own compiler launchers. For
  builds without a preset, "ccache": false in .nvim-run.json disables launchers.
  Build caching accelerates repeated compilation; initial compilation and
  linking still take their normal time.

  ASan finds memory errors; UBSan finds undefined behavior. Select the preset
  and run/test normally. Release uses optimization and may limit debugging.
  CMake presets require an existing CMakeLists.txt. Make projects keep their
  own build flags and can opt into ccache in their Makefile.

TESTS
  Space tt      Build and run all registered CTest tests
  Space ts      Select a test from the discovered list
  Space tl      Rerun the last selection
  Space tf      Rerun failed tests
  Space to      Toggle test output immediately
  Space tq      Stop the test build/process
  Enter / o     Jump from output to a file:line failure or test registration
  q / Esc       Hide output; a finishing job does not reopen the pane

  Register tests with include(CTest)/enable_testing() and add_test() in CMake.
  GoogleTest/Catch2 projects can use their CMake test discovery functions;
  any test registered with CTest is supported. Tests build before running,
  use up to four parallel workers and show failed test output. Compiler errors
  go to quickfix; test errors go to the separate output pane.

ANALYSIS
  Space cl      Run clang-tidy on the current saved file in the background
  Space ao      Toggle analysis output
  Space aq      Put findings into quickfix
  Space as      Stop analysis
  Enter / o     Jump to the selected finding

  Project .clang-tidy checks are respected. Otherwise use clang-analyzer,
  bugprone and performance checks. CMake analysis uses the selected compilation
  database; standalone files use C17/C++20. Build the project first to create
  its compilation database. Analysis does not rewrite source files.

MORE NAVIGATION AND DEBUGGING
  Space cw      Search symbols across the project
  Space cI      Show incoming calls (callers)
  Space cO      Show outgoing calls (callees)
  Space du      Toggle the full debugger layout
  Space de      Evaluate cursor expression (or visual selection)

  Debug panels include scopes, watches, threads/stack, breakpoints, REPL and
  console. Enter expands variables, e edits a value, o opens a stack frame.
  In watches, enter insert mode and type an expression to add it. Panels load
  only when requested and can stay closed while debugging.

PERFORMANCE
  Generated build/out directories skip background indexing in .clangd when
  creating local presets. :CppIndexConfig adds those exclusions explicitly
  while preserving existing project configuration. Background indexing has
  low OS priority and two workers.

  Diagnostics wait until you leave insert mode; inline text shows errors only,
  with warnings also marked in the gutter and error list. Indexing is limited
  to two clangd workers. Completion, formatting, debugger and manual search
  load on demand. Large files (1 MiB or 20,000 lines) skip expensive features.

  Space D deletes without changing registers; Space d is the debug prefix.
  Space x closes the current buffer. Space c is reserved for C/C++ commands.


See :help debug-workflow (Space dh) for all Space-based stepping, memory,
assembly and memory-check sidebar shortcuts. Space vg toggles the right pane.
